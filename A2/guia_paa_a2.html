1 Fundamentos de grafos Slides 08

Python representacoes
def matriz_adjacencia(n, edges, dirigido=False):
    """Espaço Θ(V²). Testar aresta: Θ(1). Varrer vizinhos de u: Θ(V)."""
    A = [[0] * n for _ in range(n)]
    for u, v in edges:
        A[u][v] = 1
        if not dirigido:
            A[v][u] = 1
    return A


def lista_adjacencia(n, edges, dirigido=False):
    """Espaço Θ(V + E). Varrer vizinhos de u: Θ(g(u)). Testar aresta: O(g(u))."""
    adj = [[] for _ in range(n)]
    for u, v in edges:
        adj[u].append(v)
        if not dirigido:
            adj[v].append(u)
    return adj

2 Busca em grafos: DFS, BFS, ciclos, ordem topológica Slides 09

Ideia de Trémaux (labirinto): marque cada junção visitada e volte quando achar uma já marcada ou um beco sem saída. Cada vértice é processado uma vez e cada aresta é olhada uma vez \(\Rightarrow \Theta(V+E)\) com lista de adjacência.

Busca em profundidade (DFS)

  • Usa recursão (pilha): vai o mais fundo possível, depois volta.
  • Rodando a partir de cada vértice ainda não descoberto, cobre o grafo inteiro mesmo se desconexo → produz uma floresta DFS (representada pelo vetor parent).
  • Pré-ordem = ordem de descoberta; pós-ordem = ordem em que o vértice é exaurido (todas as arestas de saída examinadas). São numerações independentes.
  • Intervalo de vida (descoberta → exaustão): para dois vértices quaisquer, os intervalos são aninhados (ancestral/descendente) ou disjuntos (primos) — nunca se cruzam ("teorema dos parênteses").
Python dfs
def dfs(n, adj):
    """
    Busca em profundidade em TODO o grafo (floresta DFS).
    Devolve pré-ordem (descoberta), pós-ordem (exaustão) e vetor de pais.
    Θ(V + E) com lista de adjacência; Θ(V²) com matriz.
    """
    pre = [-1] * n
    post = [-1] * n
    parent = [-1] * n
    cont = {"pre": 0, "post": 0}

    def visita(u):
        pre[u] = cont["pre"]; cont["pre"] += 1
        for v in adj[u]:
            if pre[v] == -1:          # v ainda não descoberto -> aresta de árvore
                parent[v] = u
                visita(v)
        post[u] = cont["post"]; cont["post"] += 1   # u exaurido

    for s in range(n):                # tenta a partir de cada vértice (grafo pode ser desconexo)
        if pre[s] == -1:
            parent[s] = s             # raiz de uma árvore da floresta
            visita(s)
    return pre, post, parent

Em Python a recursão estoura perto de 1000 níveis. Para grafos grandes use a versão iterativa (pilha explícita):

Python dfs_iterativa
def dfs_iterativa(n, adj, s):
    """Mesma ideia sem recursão (evita estourar a pilha do Python em grafos grandes)."""
    visitado = [False] * n
    ordem = []
    pilha = [s]
    while pilha:
        u = pilha.pop()
        if visitado[u]:
            continue
        visitado[u] = True
        ordem.append(u)
        for v in reversed(adj[u]):    # reversed: mesma ordem da versão recursiva
            if not visitado[v]:
                pilha.append(v)
    return ordem

Classificação das arestas (grafo dirigido)

TipoRelaçãoTeste com pre/postTeste "on-the-fly" ao olhar \((u,v)\)
Árvore\(v\) descoberto por \(u\)—\(v\) ainda não descoberto
Retorno\(v\) é ancestral de \(u\)\(pre[u] > pre[v]\) e \(post[u] < post[v]\)\(v\) descoberto e não exaurido
Avanço\(v\) é descendente de \(u\)\(pre[u] < pre[v]\) e \(post[u] > post[v]\)\(v\) exaurido e \(pre[u] < pre[v]\)
Cruzada\(v\) é primo mais velho\(pre[u] > pre[v]\) e \(post[u] > post[v]\)\(v\) exaurido e \(pre[v] < pre[u]\)
  • Cruzadas vão sempre do primo mais novo para o mais velho (se fosse o contrário, o mais novo teria sido descoberto como descendente).
  • Em grafo não dirigido só existem arestas de árvore e de retorno (classificando cada aresta na primeira vez em que é examinada).
  • Ciclo \(\iff\) existe aresta de retorno.
Python classificar_arestas
def classificar_arestas(n, adj):
    """
    Classifica cada aresta (u, v) de um grafo DIRIGIDO durante a DFS ("on-the-fly"):
      - árvore : v ainda não descoberto
      - retorno: v descoberto mas não exaurido (v é ancestral de u)  -> CICLO
      - avanço : v exaurido e pre[u] < pre[v]   (v é descendente de u)
      - cruzada: v exaurido e pre[v] < pre[u]   (v é primo mais velho)
    Θ(V + E).
    """
    pre = [-1] * n
    post = [-1] * n
    tipo = {}
    cont = [0, 0]

    def visita(u):
        pre[u] = cont[0]; cont[0] += 1
        for v in adj[u]:
            if pre[v] == -1:
                tipo[(u, v)] = "arvore"
                visita(v)
            elif post[v] == -1:
                tipo[(u, v)] = "retorno"
            elif pre[u] < pre[v]:
                tipo[(u, v)] = "avanco"
            else:
                tipo[(u, v)] = "cruzada"
        post[u] = cont[1]; cont[1] += 1

    for s in range(n):
        if pre[s] == -1:
            visita(s)
    return tipo
Python tem_ciclo
def tem_ciclo_dirigido(n, adj):
    """
    Um grafo dirigido tem ciclo  <=>  a DFS encontra uma aresta de RETORNO.
    Cores: 0 = branco (não descoberto), 1 = cinza (na pilha), 2 = preto (exaurido).
    Θ(V + E).
    """
    cor = [0] * n

    def visita(u):
        cor[u] = 1
        for v in adj[u]:
            if cor[v] == 1:           # aresta de retorno
                return True
            if cor[v] == 0 and visita(v):
                return True
        cor[u] = 2
        return False

    return any(cor[s] == 0 and visita(s) for s in range(n))


def tem_ciclo_nao_dirigido(n, adj):
    """Em grafo NÃO dirigido: ciclo <=> achar vizinho já visitado que não é o pai."""
    visitado = [False] * n
    for s in range(n):
        if visitado[s]:
            continue
        visitado[s] = True
        pilha = [(s, -1)]
        while pilha:
            u, pai = pilha.pop()
            for v in adj[u]:
                if not visitado[v]:
                    visitado[v] = True
                    pilha.append((v, u))
                elif v != pai:
                    return True
    return False

DFS iterativa com pré e pós-ordem

A dfs_iterativa acima empilha todos os vizinhos de uma vez e esquece o vértice logo depois. Por isso ela só dá a pré-ordem: não existe um momento em que se saiba que \(u\) terminou. Para ter a pós-ordem, a pilha guarda o par (vértice, índice do próximo vizinho):

  1. Descobrir \(v\): dá a pré-ordem e empilha (v, 0).
  2. Topo (u, i) com \(i < g(u)\): avança para (u, i+1) e examina a aresta \(u \to adj[u][i]\); se o vizinho não foi descoberto, desce nele.
  3. Topo com \(i = g(u)\): todos os vizinhos já foram examinados, então \(u\) está exaurido: desempilha e dá a pós-ordem.

Os vértices na pilha são exatamente os descobertos e ainda não exauridos (os "cinzas"). A ordem de visita é a mesma da versão recursiva.

Python dfs_iterativa_pre_pos
def dfs_iterativa_pre_pos(n, adj):
    """
    DFS SEM recursão que calcula pré-ordem, pós-ordem e a floresta DFS.

    Truque: a pilha guarda (vértice, índice do próximo vizinho a examinar).
    - Ao DESCOBRIR v: recebe a pré-ordem e entra na pilha com índice 0.
    - O topo examina UM vizinho por vez (avança o índice).
    - Quando o índice passa do último vizinho, o vértice está EXAURIDO:
      sai da pilha e recebe a pós-ordem.
    Visita na mesma ordem da versão recursiva. Θ(V + E).

    Por que a dfs_iterativa acima não serve para pós-ordem? Ela empilha todos
    os vizinhos de uma vez e "esquece" u logo depois: não há um momento em que
    se saiba que u terminou.
    """
    pre = [-1] * n
    post = [-1] * n
    parent = [-1] * n
    cont_pre = cont_post = 0

    for s in range(n):                        # floresta: tenta cada vértice
        if pre[s] != -1:
            continue
        parent[s] = s
        pre[s] = cont_pre; cont_pre += 1      # s descoberto
        pilha = [(s, 0)]
        while pilha:
            u, i = pilha[-1]                  # olha o topo (sem tirar)
            if i < len(adj[u]):
                pilha[-1] = (u, i + 1)        # da próxima vez, o vizinho seguinte
                v = adj[u][i]
                if pre[v] == -1:              # v não descoberto -> desce
                    parent[v] = u
                    pre[v] = cont_pre; cont_pre += 1
                    pilha.append((v, 0))
            else:                             # todos os vizinhos de u examinados
                pilha.pop()
                post[u] = cont_post; cont_post += 1   # u exaurido
    return pre, post, parent

Classificação on-the-fly sem recursão

É a mesma DFS, com uma decisão no momento em que \((u,v)\) é examinada (as regras da tabela acima):

Python classificar_arestas_iterativa
def classificar_arestas_iterativa(n, adj):
    """
    Classificação ON-THE-FLY das arestas de um grafo DIRIGIDO, sem recursão.
    É a dfs_iterativa_pre_pos + uma decisão no momento em que (u, v) é examinada:

      pre[v] == -1                  -> árvore  (v ainda não descoberto)
      pre[v] != -1 e post[v] == -1  -> retorno (v descoberto, NÃO exaurido:
                                                 está na pilha, é ancestral de u)
      post[v] != -1 e pre[u] < pre[v] -> avanço  (v exaurido, descendente de u)
      post[v] != -1 e pre[v] < pre[u] -> cruzada (v exaurido, primo mais velho)

    Existe aresta de retorno <=> o grafo tem ciclo. Θ(V + E).
    """
    pre = [-1] * n
    post = [-1] * n
    tipo = {}
    cont_pre = cont_post = 0

    for s in range(n):
        if pre[s] != -1:
            continue
        pre[s] = cont_pre; cont_pre += 1
        pilha = [(s, 0)]
        while pilha:
            u, i = pilha[-1]
            if i < len(adj[u]):
                pilha[-1] = (u, i + 1)
                v = adj[u][i]
                if pre[v] == -1:
                    tipo[(u, v)] = "arvore"
                    pre[v] = cont_pre; cont_pre += 1
                    pilha.append((v, 0))
                elif post[v] == -1:
                    tipo[(u, v)] = "retorno"
                elif pre[u] < pre[v]:
                    tipo[(u, v)] = "avanco"
                else:
                    tipo[(u, v)] = "cruzada"
            else:
                pilha.pop()
                post[u] = cont_post; cont_post += 1
    return tipo

Ordem topológica

  • Numeração em que toda aresta \((v_i, v_j)\) tem \(i < j\). Existe \(\iff\) o grafo é um DAG (dirigido acíclico).
  • Kahn (do slide): todo DAG tem uma fonte; remova fontes repetidamente (decrementando graus de entrada). Se sobrar vértice, há ciclo. \(\Theta(V+E)\).
  • Alternativa: ordenar por pós-ordem decrescente da DFS (num DAG não há aresta de retorno, então toda aresta \(u\to v\) tem \(post[u] > post[v]\)).
  • A versão "lenta" do slide (procurar fonte do zero a cada passo, removendo arestas) custa \(O(V^2(V+E))\) e destrói o grafo.
Python topologica
def ordem_topologica(n, adj):
    """
    Algoritmo de Kahn (o do slide): remove fontes (grau de entrada 0) repetidamente.
    Se sobrar vértice sem ser numerado, há ciclo -> não existe ordem topológica.
    Θ(V + E).
    """
    grau_ent = [0] * n
    for u in range(n):
        for v in adj[u]:
            grau_ent[v] += 1
    fila = deque(u for u in range(n) if grau_ent[u] == 0)
    ordem = []
    while fila:
        u = fila.popleft()
        ordem.append(u)
        for v in adj[u]:
            grau_ent[v] -= 1          # "remove" a aresta (u, v)
            if grau_ent[v] == 0:
                fila.append(v)
    return ordem if len(ordem) == n else None


def ordem_topologica_dfs(n, adj):
    """Alternativa: ordem topológica = pós-ordem da DFS invertida (supondo DAG)."""
    pre, post, _ = dfs(n, adj)
    return sorted(range(n), key=lambda v: -post[v])

Busca em largura (BFS)

  • Usa fila: visita por camadas (distância 0, 1, 2, ...). Cada vértice entra na fila uma única vez → \(\Theta(V+E)\).
  • Gera a árvore de caminhos mais curtos (SPT) em número de arestas: dist[v] é definido uma única vez e já é o mínimo.
  • Por quê: a fila sempre contém vértices com distâncias \(d\) e \(d+1\), em ordem não-decrescente — é o papel que a ordem topológica fazia no DAG.
Python bfs
def bfs(n, adj, s):
    """
    Busca em largura a partir de s. Percorre por camadas usando uma FILA.
    dist[v] = nº mínimo de arestas de s até v (-1 se inalcançável).
    parent define a árvore de caminhos mais curtos (SPT). Θ(V + E).
    """
    dist = [-1] * n
    parent = [-1] * n
    dist[s] = 0
    parent[s] = s
    fila = deque([s])
    while fila:
        u = fila.popleft()
        for v in adj[u]:
            if dist[v] == -1:         # cada vértice entra na fila UMA vez
                dist[v] = dist[u] + 1
                parent[v] = u
                fila.append(v)
    return dist, parent


def reconstruir_caminho(parent, s, t):
    """Sobe pelo vetor de pais de t até s. O(V)."""
    if parent[t] == -1:
        return None
    caminho = [t]
    while t != s:

Pontes (Simulado A2, Q2)

Uma aresta \(e=(v_i,v_j)\) é ponte se removê-la desconecta o grafo. Para uma aresta: remova-a e rode uma BFS de \(v_i\); é ponte \(\iff\) \(v_j\) não foi alcançado. \(O(V+E)\). Para todas as arestas, fazer isso \(E\) vezes custa \(O(E(V+E))\); o algoritmo de Tarjan resolve em \(O(V+E)\) com o valor low.

Python ponte
def eh_ponte(n, adj, a, b):
    """
    (Simulado A2) A aresta (a, b) é ponte <=> sem ela, b não é alcançável a partir de a.
    Uma BFS que ignora a aresta (a, b): Θ(V + E).

    visitado[a] = True
    fila = deque([a])

def todas_as_pontes(n, adj):
    """
    Tarjan: low[u] = menor pré-ordem alcançável a partir da subárvore de u usando
    no máximo UMA aresta de retorno. (u, v) de árvore é ponte <=> low[v] > pre[u].
    Θ(V + E).  (Iterativo para não estourar recursão.)
    """
    pre = [-1] * n
    low = [0] * n
    pontes = []
    t = 0
    for s in range(n):
        if pre[s] != -1:
            continue
        pre[s] = low[s] = t; t += 1
        pilha = [(s, -1, iter(adj[s]))]
        while pilha:
            u, pai, it = pilha[-1]
            avancou = False
            for v in it:
                if v == pai:
                    pai = -2                  # ignora UMA vez a aresta para o pai
                    pilha[-1] = (u, pai, it)
                    continue
                if pre[v] == -1:
                    pre[v] = low[v] = t; t += 1
                    pilha.append((v, u, iter(adj[v])))
                    avancou = True
                    break
                low[u] = min(low[u], pre[v])  # aresta de retorno
            if not avancou:
                pilha.pop()
                if pilha:
                    p = pilha[-1][0]
                    low[p] = min(low[p], low[u])
                    if low[u] > pre[p]:
                        pontes.append((p, u))
    return pontes

3 Menor caminho: DAG, BFS, Dijkstra, Bellman-Ford Slides 10

A peça central é o relaxamento de uma aresta \((u,v)\) com custo \(w\): se passar por \(u\) melhora \(v\), atualize.
$$\text{se } d[u] + w(u,v) < d[v] \;\Rightarrow\; d[v] \leftarrow d[u] + w(u,v), \quad parent[v] \leftarrow u$$
Aresta relaxada: \(d[v] - d[u] \le w(u,v)\). Tensa: \(d[v] - d[u] > w(u,v)\). Um vetor \(d\) que deixa todas as arestas relaxadas é um potencial relaxado. Todos os algoritmos abaixo só diferem na ordem em que relaxam as arestas.
  • SPT (árvore de caminhos mais curtos) / CPT (mais baratos): árvore radicada em \(v_0\) em que todo caminho a partir da raiz é ótimo em \(G\). Só existe para os vértices alcançáveis a partir de \(v_0\).
  • Sem ciclos negativos alcançáveis: todo caminho mais barato é simples e todo prefixo de um caminho ótimo é ótimo (subestrutura ótima). Com ciclo negativo, o "menor custo" vai a \(-\infty\).

Caminho mais curto em DAG

Processando os vértices na ordem topológica, quando \(u\) é processado todos que apontam para ele já foram, então \(d[u]\) já é final. Funciona com pesos negativos (não há ciclos). Trocando o sinal dos pesos, dá o caminho mais longo em DAG (que em grafo geral é NP-difícil!).

Python dag_spt
def menor_caminho_dag(n, adj, s, ordem):
    """
    Caminho mais barato em DAG: relaxa as arestas seguindo a ORDEM TOPOLÓGICA.
    Quando u é processado, d[u] já é final (todos que apontam para u vieram antes).
    Funciona com pesos negativos (DAG não tem ciclo). Θ(V + E).
    """
    d = [INF] * n
    parent = [-1] * n
    d[s] = 0
    parent[s] = s
    for u in ordem:
        if d[u] == INF:
            continue
        for v, w in adj[u]:
            if d[u] + w < d[v]:       # relaxamento
                d[v] = d[u] + w
                parent[v] = u
    return d, parent

Dijkstra

  • Cresce uma árvore \(T\) a partir de \(v_0\). A franja são as arestas de \(T\) para fora. A cada passo pega o vértice fora de \(T\) com menor \(d\), relaxa suas arestas e o insere em \(T\).
  • Exige pesos \(\ge 0\): o argumento "o menor \(d\) da franja já é definitivo" usa que estender um caminho nunca o deixa mais barato.
  • Invariantes (corretude): (1) \(parent\) define uma árvore radicada em \(v_0\); (2) as arestas de \(T\) estão relaxadas e \(d[v] < \infty \iff v \in T\); (3) toda aresta saindo de vértice já verificado está relaxada.
$$\text{vetor: } \underbrace{V}_{\text{iterações}}\cdot \underbrace{O(V)}_{\text{achar mínimo}} + O(E) = \Theta(V^2) \qquad \text{heap: } O\big((V+E)\log V\big)$$

Em grafo denso \((E \approx V^2)\) a versão com heap vira \(O(V^2 \log V)\) — pior que a de vetor. Por isso as duas existem.

Python dijkstra_lento
def dijkstra_lento(n, adj, s):
    """
    Dijkstra "array" (versão do slide cptDijkstraSlow): a cada passo procura
    linearmente o vértice não verificado de menor distância.
    Θ(V² + E) = Θ(V²)  -> melhor escolha para grafos DENSOS.
    """
    d = [INF] * n
    parent = [-1] * n
    verificado = [False] * n
    d[s] = 0
    parent[s] = s

        for v in range(n):                      # O(V) por iteração

                u = v

        for v, w in adj[u]:
            if not verificado[v] and d[u] + w < d[v]:
                d[v] = d[u] + w
                parent[v] = u
    return d, parent

def dijkstra(n, adj, s):
    """
    Dijkstra com heap mínimo (heapq). Exige pesos >= 0.
    heapq não tem "decrease-key": inserimos de novo e ignoramos entradas velhas.
    O((V + E) log V).
    """
    d = [INF] * n
    parent = [-1] * n
    d[s] = 0
    parent[s] = s
    heap = [(0, s)]
    while heap:
        du, u = heapq.heappop(heap)
        if du > d[u]:                 # entrada desatualizada ("lazy deletion")
            continue
        for v, w in adj[u]:
            if du + w < d[v]:         # relaxamento
                d[v] = du + w
                parent[v] = u
                heapq.heappush(heap, (d[v], v))
    return d, parent
Por que Dijkstra falha com peso negativo: arestas \(0\to1\) (custo 1), \(0\to2\) (custo 5), \(2\to1\) (custo \(-10\)). Dijkstra fecha o vértice 1 com \(d=1\) antes de ver \(0\to2\to1 = -5\). E somar uma constante a todos os pesos para eliminá-los não funciona: penaliza caminhos com mais arestas.

Bellman-Ford

  • Relaxa todas as arestas, \(V-1\) vezes. Depois da rodada \(i\), \(d[v]\) é no máximo o custo do melhor caminho com até \(i\) arestas.
  • Um caminho simples tem no máximo \(V-1\) arestas. Se uma \(V\)-ésima rodada ainda melhora alguém, existe ciclo negativo alcançável.
  • Retorna: indicador de sucesso (sem ciclo negativo), CPT (parent) e distâncias. \(\Theta(VE)\).
Python bellman_ford
def bellman_ford(n, edges, s):
    """
    Bellman-Ford: relaxa TODAS as arestas V-1 vezes. Aceita pesos negativos.
    Depois de i rodadas, d[v] <= custo do melhor caminho com até i arestas.
    Se a V-ésima rodada ainda melhora algo -> ciclo negativo alcançável.
    Devolve (sucesso, d, parent). Θ(V·E).
    """
    d = [INF] * n
    parent = [-1] * n
    d[s] = 0
    parent[s] = s
    for _ in range(n - 1):
        mudou = False
        for u, v, w in edges:
            if d[u] != INF and d[u] + w < d[v]:
                d[v] = d[u] + w
                parent[v] = u
                mudou = True
        if not mudou:                 # otimização: parada antecipada
            break
    for u, v, w in edges:             # rodada extra = detector de ciclo negativo
        if d[u] != INF and d[u] + w < d[v]:
            return False, d, parent
    return True, d, parent

Cuidado: as ruas são de mão dupla. Num grafo não dirigido, uma aresta negativa \(\{u,v\}\) já forma o ciclo negativo \(u\to v\to u\). Então, ou modelamos as arestas como dirigidas (como nos testes, Q02), ou a garantia do enunciado precisa ser lida como "não há como explorar recarga infinita". 4 Árvore geradora mínima: Prim, Kruskal, union-find Slides 11

MST: árvore geradora (conexa, acíclica, com todos os vértices, \(V-1\) arestas) de custo total mínimo, num grafo não dirigido e conexo. Custos podem ser negativos (ao contrário de Dijkstra, isso não atrapalha).

As duas operações e as duas propriedades

  • Adicionar uma aresta \(e \notin T\) cria exatamente um ciclo: o ciclo fundamental de \(e\). Tirar qualquer aresta desse ciclo devolve uma árvore geradora.
  • Remover uma aresta \(e \in T\) cria um corte (duas componentes): o corte fundamental de \(e\). Colocar qualquer aresta desse corte devolve uma árvore geradora.
Critério de minimalidadeEnunciadoJustifica
Por cortes\(T\) é MST \(\iff\) cada \(e \in T\) é a mais barata do seu corte fundamentalPrim
Por ciclos\(T\) é MST \(\iff\) cada \(e \notin T\) é a mais cara do seu ciclo fundamentalKruskal

Prim — cresce uma árvore

  • Começa num vértice; a cada passo adiciona a aresta mais barata da franja (uma ponta dentro, outra fora).
  • Fronteira: vértices fora de \(T\) alcançáveis pela franja; custo de um vértice = aresta mais barata que o liga a \(T\).
  • É quase o Dijkstra: a chave é \(w(u,v)\) em vez de \(d[u]+w(u,v)\).

def prim(n, adj, raiz=0):
    """
    Prim com heap: cresce UMA árvore a partir da raiz; a cada passo adiciona o
    vértice da fronteira ligado à árvore pela aresta mais barata da franja.
    O((V + E) log V).  Devolve (custo, parent) ou None se desconexo.
    """
    custo_v = [INF] * n
    parent = [-1] * n
    na_arvore = [False] * n
    custo_v[raiz] = 0
    parent[raiz] = raiz
    heap = [(0, raiz)]
    total = 0
    while heap:
        c, u = heapq.heappop(heap)
        if na_arvore[u]:
            continue
        na_arvore[u] = True
        total += c
        for v, w in adj[u]:
            if not na_arvore[v] and w < custo_v[v]:   # diferença p/ Dijkstra: compara só w
                custo_v[v] = w
                parent[v] = u
                heapq.heappush(heap, (w, v))
    return (total, parent) if all(na_arvore) else None


def prim_denso(n, W):
    """Prim com vetor (W = matriz de custos, INF = sem aresta). Θ(V²): ideal p/ grafo denso."""
    custo_v = [INF] * n
    na_arvore = [False] * n
    custo_v[0] = 0
    total = 0
    for _ in range(n):
        u = min((v for v in range(n) if not na_arvore[v]), key=lambda v: custo_v[v])
        if custo_v[u] == INF:
            return None
        na_arvore[u] = True
        total += custo_v[u]
        for v in range(n):
            if not na_arvore[v] and W[u][v] < custo_v[v]:
                custo_v[v] = W[u][v]
    return total

Kruskal — cresce uma floresta

  • Ordena as arestas por custo; percorre e adiciona cada aresta externa à floresta (que liga componentes diferentes, ou seja, não fecha ciclo). Para com \(V-1\) arestas.
  • Versão ingênua (busca a menor aresta e reatribui grupos a cada passo): \(O(V(E+V))\).
  • Com ordenação + union-find:
$$O(E\log E) + O(E \log V) = O\big((E+V)\log V\big) \qquad \text{pois } \log E < \log V^2 = 2\log V$$

Union-find

  • Cada conjunto é uma árvore; o líder é a raiz (\(group[v]=v\)). find sobe até a raiz; union pendura a raiz do menor conjunto na do maior.
  • União por tamanho ⇒ altura \(O(\log n)\): um elemento só desce de nível quando seu conjunto pelo menos dobra de tamanho.
  • Somando compressão de caminho, o custo amortizado fica quase constante (\(\alpha(n)\)).
Python union_find
class UnionFind:
    """
    Union-Find (conjuntos disjuntos) com união por tamanho + compressão de caminho.
    Com só união por tamanho (versão do slide): find O(log n).
    Com as duas otimizações: custo amortizado quase constante (α(n)).
    """
    def __init__(self, n):
        self.pai = list(range(n))
        self.tam = [1] * n

    def find(self, x):
        raiz = x
        while raiz != self.pai[raiz]:
            raiz = self.pai[raiz]
        while x != raiz:              # compressão de caminho
            self.pai[x], x = raiz, self.pai[x]
        return raiz

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False              # já estavam no mesmo conjunto (formaria ciclo)
        if self.tam[ra] < self.tam[rb]:
            ra, rb = rb, ra
        self.pai[rb] = ra             # menor pendurado no maior
        self.tam[ra] += self.tam[rb]
        return True

def kruskal(n, edges):
    """
    Kruskal: ordena as arestas por custo e adiciona cada uma que NÃO forma ciclo
    (líderes diferentes no union-find). Cresce uma FLORESTA até virar árvore.
    O(E log E) = O(E log V).  Devolve (custo, arestas) ou None se desconexo.
    """
    uf = UnionFind(n)
    custo, mst = 0, []
    for u, v, w in sorted(edges, key=lambda e: e[2]):
        if uf.union(u, v):
            custo += w
            mst.append((u, v, w))
            if len(mst) == n - 1:
                break
    return (custo, mst) if len(mst) == n - 1 else None

5 Fluxo máximo: Ford-Fulkerson, Edmonds-Karp, corte mínimo Slides 12

Definições

  • Rede: grafo dirigido com capacidade \(c_{ij} > 0\) em cada aresta; origem \(v_0\) e destino \(v_f\).
  • Fluxo: valor \(f_{ij}\) por aresta com \(0 \le f_{ij} \le c_{ij}\) e conservação: saldo (saída − entrada) zero em todo vértice exceto \(v_0\) e \(v_f\).
  • Intensidade do fluxo = saldo em \(v_0\). Aresta saturada: \(f=c\); vazia: \(f=0\).
  • Um fluxo pode ser decomposto em caminhos simples de \(v_0\) a \(v_f\); a soma das quantidades é a intensidade.
"Todo caminho de \(v_0\) a \(v_f\) tem uma aresta saturada" não garante fluxo máximo (pode ser preciso desfazer fluxo numa aresta). Todo fluxo máximo tem essa propriedade, mas a recíproca é falsa.

Pseudocaminhos e capacidade residual

  • Pseudocaminho: pode usar arestas no sentido certo (diretas) ou ao contrário (reversas).
  • Aumentador: nenhuma aresta direta saturada e nenhuma reversa vazia.
  • Capacidade residual: \(\delta_{ij} = c_{ij} - f_{ij}\) (direta) e \(\delta_{ij} = f_{ji}\) (reversa); a do pseudocaminho é o mínimo delas.
  • Enviar \(u \le \delta\) unidades: soma \(u\) nas diretas, subtrai \(u\) nas reversas ⇒ a intensidade aumenta \(u\).
Ford-Fulkerson: comece com fluxo nulo; enquanto existir pseudocaminho aumentador, envie \(\delta\) por ele. Cada iteração custa \(O(E)\) e soma pelo menos 1 unidade ⇒ \(O(E\cdot f_{max})\) — não é polinomial (depende do valor das capacidades).
Implementação: para cada aresta original \(e_{ij}\), crie uma aresta virtual \(e_{ji}\) (capacidade 0) que referencia a original. Empurrar fluxo numa delas tira da outra.

Cortes e o teorema fluxo-máximo / corte-mínimo

  • Corte: partição \((V_1, V_2)\) com \(v_0 \in V_1\) e \(v_f \in V_2\). Capacidade = soma das capacidades das arestas diretas \(V_1 \to V_2\) (reversas não contam).
  • Para qualquer fluxo e qualquer corte: intensidade \(= outflow(V_1) - inflow(V_1) \le\) capacidade do corte.
  • Teorema: intensidade do fluxo máximo = capacidade do corte mínimo. Para achar o corte: depois do fluxo máximo, \(V_1\) = vértices alcançáveis a partir de \(v_0\) no grafo residual.
$$\max_{f} \; |f| \;=\; \min_{(V_1,V_2)} \sum_{i \in V_1,\, j \in V_2} c_{ij}$$

Edmonds-Karp

  • É Ford-Fulkerson escolhendo o pseudocaminho aumentador mais curto (BFS).
  • Aresta crítica: residual igual ao do caminho (zera depois do envio). Os comprimentos dos caminhos aumentadores nunca diminuem, e uma aresta só pode voltar a ser crítica num caminho pelo menos 2 arestas mais longo.
$$\underbrace{O(V)}_{\text{vezes que cada aresta é crítica}} \times \underbrace{E}_{\text{arestas}} = O(VE)\ \text{caminhos} \quad\Rightarrow\quad O(VE)\cdot O(E) = O(VE^2)$$
Python edmonds_karp
def fluxo_maximo(n, arestas, s, t):
    """
    Ford-Fulkerson com busca em LARGURA (Edmonds-Karp).
    Cada aresta original (u, v, c) ganha uma aresta "virtual" (v, u, 0) — a reversa.
    Capacidade residual de uma aresta = cap - fluxo. Empurrar δ numa aresta
    tira δ da sua reversa (é isso que permite "desfazer" fluxo).
    O(V · E²).  Devolve (valor do fluxo, grafo residual).
    """
    # grafo residual: g[u] = lista de [v, capacidade, índice da reversa em g[v]]
    g = [[] for _ in range(n)]
    for u, v, c in arestas:
        g[u].append([v, c, len(g[v])])
        g[v].append([u, 0, len(g[u]) - 1])

    total = 0
    while True:
        # BFS procurando caminho aumentador (o MENOR em nº de arestas)
        pai = [None] * n              # pai[v] = (u, índice da aresta em g[u])
        pai[s] = (s, -1)
        fila = deque([s])
        while fila and pai[t] is None:
            u = fila.popleft()
            for i, (v, cap, _) in enumerate(g[u]):
                if cap > 0 and pai[v] is None:
                    pai[v] = (u, i)
                    fila.append(v)
        if pai[t] is None:            # não há caminho aumentador -> fluxo máximo
            return total, g
        # capacidade residual δ do caminho = menor residual nas arestas
        delta = INF
        v = t
        while v != s:
            u, i = pai[v]
            delta = min(delta, g[u][i][1])
            v = u
        # empurra δ: direta perde δ de residual, reversa ganha δ
        v = t
        while v != s:
            u, i = pai[v]
            g[u][i][1] -= delta
            rev = g[u][i][2]
            g[v][rev][1] += delta
            v = u
        total += delta

    fila = deque([s])
    while fila:
        u = fila.popleft()
        for v, cap, _ in g[u]:
            if cap > 0 and not alcancavel[v]:
                alcancavel[v] = True
                fila.append(v)
    corte = [(u, v, c) for u, v, c in arestas if alcancavel[u] and not alcancavel[v]]

\(P \subseteq NP\): se dá para decidir em tempo polinomial, o verificador simplesmente ignora o certificado e resolve. Se \(P = NP\) ou não é um problema aberto desde 1971; acredita-se em \(P \ne NP\).

Redução polinomial — a direção importa

\(\alpha \le_p \beta\) ("\(\alpha\) se reduz a \(\beta\)") quando existe uma transformação \(T\) polinomial que leva qualquer instância \(i_\alpha\) em \(i_\beta = T(i_\alpha)\) com
$$i_\beta \text{ tem resposta SIM} \iff i_\alpha \text{ tem resposta SIM}$$
Leitura: \(\beta\) é pelo menos tão difícil quanto \(\alpha\). Se \(\beta \in P\) então \(\alpha \in P\). Exemplo do slide: "o \(i\)-ésimo menor é \(x\)?" se reduz a ordenar e comparar \(A[i]==x\).

Para provar que \(X\) é NP-completo: (1) mostre \(X \in NP\) (dê o certificado e o verificador polinomial); (2) escolha um NP-completo conhecido \(Y\) e mostre \(Y \le_p X\). Cook e Levin (1971) deram o primeiro (SAT).

Se um NP-completo estiver em P, então P = NP: todo \(C \in NP\) satisfaz \(C \le_p A\); compondo a redução com o algoritmo polinomial de \(A\), \(C\) fica polinomial. Logo \(NP \subseteq P\), e com \(P \subseteq NP\) vem a igualdade.

def mochila_fracionaria(itens, W):
    """Guloso por razão valor/peso. itens = [(peso, valor)]. Θ(n log n)."""
    total = 0.0
    for w, v in sorted(itens, key=lambda it: it[1] / it[0], reverse=True):

def par_mais_proximo(pontos):
    """
    Dividir e conquistar (slides 07 / sua AS). Ordena por x uma vez; cada chamada
    devolve a lista ordenada por y (merge), evitando reordenar: T(n) = 2T(n/2) + O(n)
    = Θ(n log n).
    """
    def dist(p, q):
        return sqrt((p[0] - q[0]) ** 2 + (p[1] - q[1]) ** 2)

    def rec(px):                      # px ordenado por x; devolve (d, py)
        n = len(px)
        if n <= 3:
            d = min((dist(px[i], px[j]) for i in range(n) for j in range(i + 1, n)),
                    default=INF)
            return d, sorted(px, key=lambda p: p[1])
        m = n // 2
        xm = px[m][0]
        dl, ly = rec(px[:m])
        dr, ry = rec(px[m:])
        d = min(dl, dr)
        py, i, j = [], 0, 0           # merge por y: O(n)
        while i < len(ly) or j < len(ry):
            if j == len(ry) or (i < len(ly) and ly[i][1] <= ry[j][1]):
                py.append(ly[i]); i += 1
            else:
                py.append(ry[j]); j += 1
        faixa = [p for p in py if abs(p[0] - xm) < d]
        for i in range(len(faixa)):   # cada ponto compara com no máx. 7 seguintes
            for j in range(i + 1, min(i + 8, len(faixa))):
                if faixa[j][1] - faixa[i][1] >= d:
                    break
                d = min(d, dist(faixa[i], faixa[j]))
        return d, py

    return rec(sorted(pontos))[0]

def contar_inversoes(A):
    """Merge sort contando inversões entre metades. Θ(n log n)."""
    if len(A) <= 1:
        return 0, list(A)
    m = len(A) // 2
    il, L = contar_inversoes(A[:m])
    ir, R = contar_inversoes(A[m:])
    res, i, j, inv = [], 0, 0, 0
    while i < len(L) and j < len(R):
        if L[i] <= R[j]:
            res.append(L[i]); i += 1
        else:
            res.append(R[j]); j += 1
            inv += len(L) - i         # R[j] é menor que todos os L[i:] restantes
    res += L[i:] + R[j:]
    return il + ir + inv, res

def mochila01(pesos, valores, W):
    """
    PD bottom-up: M[j][c] = melhor valor usando os j primeiros itens com capacidade c.
    M[j][c] = max(M[j-1][c], v_j + M[j-1][c - w_j])  (se w_j <= c)
    Θ(nW) — PSEUDO-polinomial (W é um valor, ocupa log W bits).
    """
    n = len(pesos)
    M = [[0] * (W + 1) for _ in range(n + 1)]
    for j in range(1, n + 1):
        w, v = pesos[j - 1], valores[j - 1]
        for c in range(W + 1):
            M[j][c] = M[j - 1][c]
            if w <= c:
                M[j][c] = max(M[j][c], v + M[j - 1][c - w])
    # reconstrução: anda de trás para frente
    itens, c = [], W
    for j in range(n, 0, -1):
        if M[j][c] != M[j - 1][c]:
            itens.append(j - 1)
            c -= pesos[j - 1]
    return M[n][W], itens[::-1]

def troco_minimo(moedas, valor):
    """
    (A2 2025.2, Q3) PD: dp[x] = menor nº de moedas para formar x.
    dp[x] = 1 + min(dp[x - m]) para toda moeda m <= x.
    Guloso só funciona em sistema canônico: moedas [1,5,6,9], valor 11 ->
    guloso dá 9+1+1 (3 moedas), ótimo é 5+6 (2 moedas).
    Θ(valor · nº de moedas) — pseudo-polinomial.
    """
    dp = [0] + [INF] * valor
    escolha = [-1] * (valor + 1)
    for x in range(1, valor + 1):
        for m in moedas:
            if m <= x and dp[x - m] + 1 < dp[x]:
                dp[x] = dp[x - m] + 1
                escolha[x] = m
    if dp[valor] == INF:
        return -1
    usadas = []
    while valor > 0:
        usadas.append(escolha[valor])
        valor -= escolha[valor]
    return sorted(usadas)

def agendamento_ponderado(tarefas):
    """
    (Simulado A2, Q3) tarefas = [(inicio, fim, valor)].
    Ordena por fim; p(j) = última tarefa i < j com fim_i <= inicio_j (busca binária).
    dp[j] = max(dp[j-1], valor_j + dp[p(j)])     ->  Θ(n log n).
    """
    import bisect
    T = sorted(tarefas, key=lambda t: t[1])
    fins = [t[1] for t in T]
    n = len(T)
    dp = [0] * (n + 1)                 # dp[j] considera as j primeiras tarefas
    for j in range(1, n + 1):
        ini, fim, val = T[j - 1]
        p = bisect.bisect_right(fins, ini, 0, j - 1)   # nº de tarefas compatíveis antes
        dp[j] = max(dp[j - 1], val + dp[p])
    escolhidas, j = [], n               # reconstrução
    while j > 0:
        ini, fim, val = T[j - 1]
        p = bisect.bisect_right(fins, ini, 0, j - 1)
        if val + dp[p] >= dp[j - 1] and dp[j] == val + dp[p]:
            escolhidas.append(T[j - 1])
            j = p
        else:
            j -= 1
    return dp[n], escolhidas[::-1]

def lcs(a, b):
    """Maior subsequência comum. m[i][j] usa prefixos a[:i], b[:j]. Θ(p·q)."""
    p, q = len(a), len(b)
    m = [[0] * (q + 1) for _ in range(p + 1)]
    for i in range(1, p + 1):
        for j in range(1, q + 1):
            if a[i - 1] == b[j - 1]:
                m[i][j] = m[i - 1][j - 1] + 1
            else:
                m[i][j] = max(m[i - 1][j], m[i][j - 1])
    return m[p][q]

T23★★★ MST

Fonte: Slides 11
Ver resposta

T25★★★ MST

Fonte: Slides 11
Ver resposta

Cada conjunto é uma árvore com o líder na raiz. find sobe pelos pais até a raiz; union pendura a raiz do menor conjunto na do maior. Na seleção do maior número de tarefas compatíveis, por que ordenar por término e não por início, duração ou nº de conflitos?

Fonte: Slides 07
Ver resposta

Início: uma tarefa longa que começa cedo bloqueia várias. Menor duração: uma curta no meio pode conflitar com duas que caberiam. Menor nº de conflitos também tem contraexemplo (slide). Término mais cedo deixa o máximo de tempo livre para o resto (argumento de troca). \(\Theta(n\log n)\).

T58★★★ Técnicas

Enuncie o Teorema Mestre (forma simplificada) e aplique à contagem de inversões com e sem ordenação explícita.

Fonte: Slides 07
Ver resposta
$$T(n) = aT(n/b)+\Theta(n^k):\ \ a<b^k \Rightarrow \Theta(n^k);\ \ a=b^k \Rightarrow \Theta(n^k\log n);\ \ a>b^k\Rightarrow\Theta(n^{\log_b a})$$

Com merge devolvendo a lista ordenada: \(2T(n/2)+\Theta(n) = \Theta(n\log n)\). Ordenando as metades a cada nível: \(2T(n/2)+\Theta(n\log n) = \Theta(n\log^2 n)\) (fora da forma simples do teorema; resolva pela árvore de recursão).

T59★★★ Fundamentos

Diferencie subgrafo, subgrafo gerador, subgrafo induzido e subgrafo próprio.

Fonte: Slides 08
Ver resposta

Subgrafo: \(V'\subseteq V\), \(E'\subseteq E\). Gerador: \(V'=V\). Induzido: escolhe \(V'\) e \(E'\) são todas as arestas de \(E\) entre vértices de \(V'\). Próprio: \(H \subset G\) estrito (diferente de \(G\)).

T60★★★ Fundamentos

Qual a complexidade de verificar se H é subgrafo de G (mesmos vértices) com matriz? E com lista? Como otimizar a versão com lista?

Fonte: Slides 08 — Ex. 3
Ver resposta

Matriz: \(\Theta(V^2)\). Lista (para cada aresta de H, percorre a lista de G): \(O(E_H \cdot V)\) no pior caso. Otimização: colocar os vizinhos de cada vértice de G num conjunto hash (ou ordenar as listas) ⇒ \(O(V + E_G + E_H)\).

T61★★★ Menor caminho

Quando existe uma SPT/CPT com raiz \(v_i\)?

Fonte: Slides 10
Ver resposta

A SPT de \(G\) existe se todos os vértices são alcançáveis a partir de \(v_i\); senão, existe para o subgrafo induzido pelos alcançáveis. A CPT exige ainda que não haja ciclo negativo alcançável.

T62★★★ MST

Que outra propriedade a MST tem sobre a maior aresta dos caminhos?

Fonte: Extra
Ver resposta

O caminho entre \(u\) e \(v\) na MST minimiza o maior peso de aresta entre todos os caminhos de \(u\) a \(v\) (caminho minimax / gargalo). Por isso a Q35 (menor esforço) também sai com Kruskal parando quando os extremos se conectam.

T63★★★ Fluxo

Como tratar várias fontes/sorvedouros e capacidades nos vértices?

Fonte: Extra
Ver resposta

Várias fontes/sorvedouros: superfonte ligada a todas as fontes e todos os sorvedouros ligados a um supersorvedouro, com capacidade infinita. Capacidade em vértice \(v\): divida em \(v_{in}\to v_{out}\) com essa capacidade; arestas que chegavam em \(v\) chegam em \(v_{in}\) e as que saíam saem de \(v_{out}\).

T64★★★ Fluxo

Se todas as capacidades são inteiras, o fluxo máximo pode ser escolhido inteiro?

Fonte: Slides 12
Ver resposta

Sim. Ford-Fulkerson começa do fluxo 0 e cada \(\delta\) é um mínimo de capacidades residuais inteiras, então o fluxo continua inteiro em todas as iterações (teorema da integralidade). É o que justifica o uso de fluxo para emparelhamento.

T65★★★ Complexidade

Diferencie problema tratável, intratável e indecidível.

Fonte: Slides 13
Ver resposta

Tratável: tem algoritmo polinomial. Intratável: o melhor algoritmo é superpolinomial (exponencial, fatorial); recorre-se a aproximações/heurísticas. Indecidível: não existe algoritmo correto para todas as entradas (problema da parada).

T66★★★ Técnicas

Compare PD top-down e bottom-up.

Fonte: Slides 07
Ver resposta

Top-down: recursiva, começa pelo problema grande e só resolve subproblemas necessários, guardando em cache (memoization). Bottom-up: iterativa, preenche a tabela do menor para o maior. Em geral mesma complexidade; bottom-up evita recursão profunda, top-down pode pular estados inúteis.

T67★★★ Técnicas

Por que o guloso funciona na mochila fracionária e falha na 0/1?

Fonte: Slides 07
Ver resposta

Na fracionária, pegar o item de maior valor/peso (e uma fração do último) é ótimo por troca: qualquer peso usado com razão menor pode ser trocado por peso de razão maior. Na 0/1 não dá para fracionar: com \(W=50\), itens (10 kg, 60), (20 kg, 100), (30 kg, 120), o guloso por razão pega os dois primeiros (160), mas o ótimo é 220.
